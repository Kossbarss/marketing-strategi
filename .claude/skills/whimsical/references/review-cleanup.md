# Перевірка і «прибирання» дошки

## Як дивитися

1. `fetch({id: board_id})` — список обʼєктів (групи згорнуті).
2. `fetch({id: board_id, detail: "detailed", spatial: true})` — координати і розміри.
3. `fetch({id: board_id, image: true})` — PNG. Для великої дошки — `scope` / `crop_ids` / `viewport`.
4. Всередину діаграми — `scope: <diagram_id>`.

## Чек-лист

**Структура і логіка**
- [ ] У кожного рішення (`diamond`) підписані всі гілки.
- [ ] Немає «висячих» вузлів без вхідних/вихідних звʼязків (крім старту/фінішу).
- [ ] Немає циклів без виходу.
- [ ] Схема відповідає брифу / коду / процесу, який описує (звір по джерелу).
- [ ] Тип діаграми відповідає задачі (дерево не намальоване flowchart-ом і навпаки).

**Візуал**
- [ ] Немає накладань обʼєктів і діаграм.
- [ ] Текст не обрізаний, підписи ≤ 5 слів.
- [ ] Кольори несуть зміст і узгоджені (див. таблицю ролей у SKILL.md), не більше 4–5 кольорів.
- [ ] Один напрям потоку в межах діаграми.
- [ ] Заголовки розділів є і мають однаковий розмір.

**Дані**
- [ ] У таблицях немає порожніх обовʼязкових клітинок, статуси кольорові.
- [ ] Цифри в схемі збігаються з таблицями.

## Як виправляти

| Проблема | Дія |
|---|---|
| Накладання / хаос | `auto_layout` на дошку або діаграму |
| Неправильний підпис | `edit` → `find_replace` (діаграми) або `update` (окремі обʼєкти) |
| Зайвий вузол | `edit` → `delete_by_text` / `delete` |
| Структурна помилка у схемі | Видалити діаграму, створити заново одним `create` на тому ж місці (`x/y` з detailed fetch) |
| Таблиці бракує колонки | Видалити і створити заново |

Після виправлень — повторно `fetch image:true`. Результат звіту: що знайдено → що виправлено → що лишилось на рішення людини.
Коментарі з зауваженнями на дошці — `comment_edit`; прочитати відгуки команди — `comment_read`.
